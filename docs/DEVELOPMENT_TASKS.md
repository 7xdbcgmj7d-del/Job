# AI Job Copilot DEVELOPMENT_TASKS.md

> 文档目的：给 Codex 执行开发任务使用。Codex 每次只执行一个 Task，避免一次性大改导致功能崩坏。
>
> 开发原则：小步提交、每步可验收、优先做产品减法，再做 AI 能力增强。

---

## 0. Codex 执行总规则

### 0.1 开发前必须阅读

在执行任何任务前，请先阅读以下文档：

```text
docs/PRD.md
docs/AI_DESIGN.md
docs/ITERATION_PLAN.md
```

优先级：

```text
DEVELOPMENT_TASKS.md > PRD.md > AI_DESIGN.md > ITERATION_PLAN.md
```

如果文档之间出现冲突，以 `DEVELOPMENT_TASKS.md` 为准。

---

### 0.2 每次只做一个 Task

不要一次性完成多个任务。

每次只执行当前指定的 Task，例如：

```text
只做 Task 1：取消 MVP 前台登录
```

不要顺手修改其他模块。

---

### 0.3 不要做的事

除非任务明确要求，不要做以下事情：

```text
不要重构整个项目结构
不要删除底层 auth 代码
不要接真实大模型 API
不要新增登录 / 注册流程
不要新增云端同步
不要新增数据库迁移
不要新增复杂状态管理
不要新增复杂 UI 动效
不要把 Prompt / 评测集 / Bad Case 暴露到普通用户前台
不要改动与当前任务无关的页面
```

---

### 0.4 每个 Task 完成后必须检查

每个任务完成后，请确保：

```text
npm run build 可以通过
页面没有白屏
原有岗位 / 简历 / 面试数据流程不被破坏
主路径操作比之前更简单
```

如果项目当前已有 lint / typecheck 命令，也需要运行。

---

### 0.5 提交要求

每个 Task 单独提交，commit message 使用以下格式：

```text
feat: xxx
fix: xxx
docs: xxx
refactor: xxx
```

示例：

```text
feat: remove login entry from MVP user flow
feat: simplify add job dialog
feat: add AI match mock result
```

# Task 1：取消 MVP 前台登录

## 目标

MVP 阶段取消前台登录入口，让用户打开产品后无需登录即可使用核心功能。

AI Job Copilot 是阶段性求职工具，当前版本重点是打开即用，不是账号体系。

---

## 改动范围

查找并处理以下 UI：

```text
右侧顶部登录卡片
左下角登录按钮
未登录 / 访客身份提示
点击登录账号文案
为了登录而存在的入口
```

---

## 具体要求

1. 删除或隐藏右侧顶部的大面积登录卡片。
2. 删除或隐藏左下角登录按钮。
3. 删除明显的“未登录 / 访客”状态展示。
4. 不要删除底层 auth 代码。
5. 不要改动后端 auth 逻辑。
6. 不要新增新的登录入口。
7. 所有核心功能默认不登录也可使用。

---

## 不要改

```text
不要删除 auth 相关文件
不要删除登录 API
不要新增账号同步功能
不要改动岗位 / 简历 / 面试的数据结构
不要改动 AI 匹配分析逻辑
```

---

## 验收标准

- 打开产品后，不再看到强登录入口。
- 左下角不再出现登录按钮。
- 页面不再反复提示未登录或访客状态。
- 不登录也能进入首页、岗位、简历、面试和设置页面。
- 不登录也能添加岗位、编辑岗位、管理简历和面试。
- `npm run build` 通过。

# Task 4：新增“保存并 AI 分析”按钮

## 目标

让添加岗位流程自然接入 AI 决策闭环。

用户不只是保存岗位，而是可以保存后直接进入 AI 分析。

---

## 改动范围

添加岗位弹窗底部按钮区域。

---

## 具体要求

保留原有按钮：

```text
保存岗位
```

新增按钮：

```text
保存并 AI 分析
```

交互逻辑：

1. 点击“保存岗位”：保持原有保存逻辑。
2. 点击“保存并 AI 分析”：先保存岗位，再进入该岗位的 AI 分析入口。
3. 如果当前还没有真实 AI 分析页面，可以跳转到岗位详情页或打开 mock AI 分析区域。
4. 如果当前没有岗位详情页，可以先在保存后展示提示：

```text
岗位已保存，AI 分析功能即将接入。
```

但优先建议跳转到一个可承载 AI 分析的页面或状态。

---

## 不要改

```text
不要破坏原有保存岗位逻辑
不要直接调用真实 AI API
不要改动数据库结构，除非现有保存逻辑必须调整
不要删除取消 / 关闭弹窗能力
```

---

## 验收标准

- “保存岗位”仍可正常保存。
- “保存并 AI 分析”可以保存岗位。
- 点击“保存并 AI 分析”后，用户能感知下一步进入 AI 分析流程。
- 不影响原有添加岗位功能。
- `npm run build` 通过。

# Task 7：定义 AIMatchResult 类型

## 目标

为后续真实 AI API 接入和结构化展示建立统一数据结构。

---

## 改动范围

新增或更新 AI 相关类型文件。

建议路径可根据项目结构选择：

```text
src/types/ai.ts
src/lib/types/ai.ts
src/features/ai/types.ts
```

---

## 类型定义

请定义以下类型：

```ts
export type AIMatchLevel = "high" | "medium" | "low";

export type AIDecision = "recommend" | "conditional" | "not_recommend";

export type AIMatchResult = {
  jobId?: string;
  resumeId?: string;
  score: number;
  level: AIMatchLevel;
  decision: AIDecision;
  decisionReason: string;
  jdSummary: {
    responsibilities: string[];
    requiredSkills: string[];
    bonusSkills: string[];
    hiddenRequirements: string[];
    risks: string[];
  };
  strengths: string[];
  weaknesses: string[];
  suggestions: string[];
  resumeRewriteTips: string[];
  interviewQuestions: string[];
  createdAt: string;
};
```

---

## 可选：新增展示映射

可以新增：

```ts
export const AI_MATCH_LEVEL_LABELS = {
  high: "高匹配",
  medium: "中匹配",
  low: "低匹配",
} as const;

export const AI_DECISION_LABELS = {
  recommend: "建议优先投递",
  conditional: "建议优化后投递",
  not_recommend: "不建议优先投递",
} as const;
```

---

## 不要改

```text
不要接真实 AI API
不要新增数据库迁移
不要改动 UI，除非为了使用类型做很小调整
```

---

## 验收标准

- 项目中存在统一的 AIMatchResult 类型。
- AI mock 结果可以使用该类型。
- TypeScript 编译通过。
- `npm run build` 通过。
